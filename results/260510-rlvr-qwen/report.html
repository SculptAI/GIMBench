配置-效果关系总结：
配置因素对 GPQA/MMLU对 Match对 Code
math_verify（vs 精确匹配）↑ 推理更好↓ 匹配更差↑ 代码更好
temp=1.2（vs 1.0）~ 混合↓ 匹配更差↑ 代码更好
少数据 1000（vs 2000）~ 混合↓ 匹配更差↑ 代码更好

核心 trade-off：math_verify + 高温度 + 少数据 → 推理/代码更好，但匹配更差。精确匹配 + 低温度 + 多数据 → 匹配更好，但推理/代码更差。

未尝试的组合：math_verify + 低温度 + 多数据（可能同时获得推理和匹配的优势）。

十、PPL Benchmark 设计问题

PPL benchmark 只测流畅度，不测正确性，耗时占总评测 47%（60 分钟）。
  • alpha=0.2 归一化把 PPL 的 10 倍差异压缩到 37%
  • 参考模型太小（gemma-3-270m），PPL 估计 noisy
  • 没有人类评估相关性验证

建议：缩减到 200 样本，或加入正确性评估。
